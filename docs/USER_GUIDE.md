# 使用指南

本文介绍 0.1.2-Beta1 已包含的功能和20次去极值稳定性窗口。截图和示例数据均为模拟内容。运行状态页显示的版本来自当前运行的插件二进制；真实宿主兼容性尚未声明验证。

**下一步：** 先按[安装与权限](#安装与权限)确认管理 API 权限，再配置账号并启用自动管理。

## 账号与调用组

插件只对明确添加的 API Key 账号执行自动调度；不会自动管理 OAuth 账号。各平台独立管理账号分组和规则。

| 调度顺序 | 调用组 | 默认优先级 | 说明 |
| --- | --- | ---: | --- |
| 独立 | 常开 `always_on` | 5 | 与普通调用组独立持续开放；忽略质量和倍率策略。 |
| 1 | 优秀 `excellent` | 6 | 普通调用组首选。 |
| 2 | 良好 `good` | 7 | 优秀组没有可调用账号时接续。 |
| 3 | 一般 `general` | 8 | 前两组没有可调用账号时接续。 |
| 4 | 备用 `reserve` | 9 | 前三组没有可调用账号时接续。 |
| - | 临时 `temporary` | 99 | 始终关闭，不参与自动调用；新账号默认进入此组。 |

普通组的先后顺序固定；各平台可配置组优先级数字，但不会改变分组顺序。临时组始终关闭。账号监控按组展示正常和不可调用账号，空组隐藏。调度状态表示宿主调度开关，不表示账号此刻正在处理请求。页面目录导航栏最右侧的按钮按状态显示“启动监控”或“停止监控”。账号表运行状态栏在重试等待期间显示每秒更新的倒计时。

## 倍率

新账号默认使用上游倍率方案。有效的上游快照显示为上游倍率；快照不支持、缺失、过期或读取失败时，采用默认 `1.0×`，显示“上游不支持 默认 1.0×”。不会自动切换到账号保存的固定倍率。明确选择固定方案后，才采用该账号固定值。

插件不会自动开启宿主的上游倍率探测。需要上游倍率时，先在宿主启用探测，并确认管理 API 密钥有权读取倍率快照。默认 `1.0×` 参与普通组倍率规则；例如倍率上限为 `0.2×` 时会超过上限。常开组忽略倍率限制。

## 采样与规则

启用自动管理后才开始用量采样。默认采样间隔为 60 秒，可设置为 15 至 3600 秒。每个可配置组（包括常开组）都可设置 `min_input_tokens`，默认 40000 Token（40K）。请求容量按 `input_tokens + cache_creation_tokens + cache_read_tokens` 计算；容量字段齐全且总量达到本组门槛的请求，才进入缓存、首字时间和质量采样。低于门槛的请求记为小请求剔除；容量字段有缺失则记为容量未知剔除，不算小请求。常开组也过滤质量采样，但质量异常不会触发常开组停用。

稳定性窗口按账号合并所有可参与质量判断的模型和请求类型，每 20 个容量合格请求形成一个互不重叠窗口，不按定时采集轮次累计。按时间从旧到新累计，第 20 个合格请求封闭窗口；后续请求进入下一窗口。20次请求全部计入窗口及模型调用统计；去极值只影响指标均值。重复刷新同一批记录不会累加或重复计数。每窗模型/请求类型有效请求数合计为20，分项只作诊断，不单独判定质量故障或恢复。`request_type=cyber` 的策略拒绝请求、空模型、空请求类型和 `unknown` 类型不进入质量判定。

| 规则 | 默认值 | 口径 |
| --- | ---: | --- |
| 最小输入容量 `min_input_tokens` | 40,000 Token（40K） | 每个组分别设置；按 `input_tokens + cache_creation_tokens + cache_read_tokens` 求和，达到门槛才计入采样。低于门槛和容量字段未知分别剔除、分别计数。 |
| 缓存命中比例下限 | 80% | 对完整窗口的20个逐请求缓存比例观测排序，去掉最高、最低各2项，以剩余16项的算术平均判断；不按 Token 加权。 |
| 平均首字时间上限 | 10,000 ms | 首字观测完整的20个样本分别排序去掉最高、最低各2项，以剩余16项的算术平均判断。 |
| 有效倍率上限 | 0.2× | 当前选择的上游倍率或固定倍率；作为独立策略立即检查。 |
| 质量异常确认 | 2 个坏窗口 | 窗口不重叠，且默认至少跨越 180 秒；启动观察宽限默认 180 秒。 |
| 恢复观察 | 2 个健康窗口 | 还须满足默认 300 秒的最短观察时间。 |
| 重试冷却 | 300 秒 | 重复失败后逐次翻倍，最长 24 小时。 |

`confirmation_seconds` 和 `recovery_seconds` 均可设为 60 至 86400 秒。缓存比例计算为：

```text
cache_read_tokens / (input_tokens + cache_creation_tokens + cache_read_tokens)
```

缓存比例按每次请求的 `cache_read_tokens / (input_tokens + cache_creation_tokens + cache_read_tokens)` 先行计算。仅完整的20请求账号窗口计算质量指标；未满20的尾窗只显示已有观测，不作健康或异常判定。完整窗口的缓存比例和首字时间分别对各自的20项排序，独立去除最高、最低各2项，再以16项算术平均形成账号窗口指标。20次请求全部计入窗口及模型调用统计；去极值只影响指标均值，不计为小请求或容量未知剔除。模型/请求类型汇总显示原始按Token加权的缓存比例和未去极值的首字时间均值，不参与独立质量判定。完整窗口首字观测不足20个样本时为未知，不得依靠去极值判为健康；“首字满20”表示原始观测完整，账号均值使用16项。账号稳定性只按窗口总指标判定。默认连续两个坏窗口且至少跨越180秒才确认故障，两个健康窗口且满足默认300秒观察时间才恢复。明确设置的倍率上限单独判断，超限时立即退出调用资格，不等待质量确认，也不增加故障次数或退避级别。缓存数据不完整、分页失败或没有流量时，受影响指标为未知；缺少流量既不是健康证据，也不算新增故障。

用量分页最多扫描 5000 条记录；到达上限且所需样本仍不完整时，会标记受影响的指标为未知，不会将其当作零。

若扫描没有覆盖上一完整窗口的边界，当前账号窗口进度和本窗剔除数显示未知，保留已完成的历史。历史行中的“异常”表示该账号窗口总指标异常；账号停用仍须满足连续异常窗口与确认时长，常开组不因质量异常停用。

账号监控表直接为每个账号连续展示最近三个已完成账号窗口，最新在前，在原行之外增加最多两行历史。每个完整窗口按20次请求统计，列出周期、时间范围、容量门槛、两类容量剔除数、账号级缓存/首字结果及健康/异常/未知结论；运行详情显示窗口内各模型和请求类型的汇总、原始按 Token 加权缓存比例和未去极值首字均值，仅作诊断。当前不足20请求的尾窗只显示已有观测，不作质量判定。Health JSON 的 `quality_sampling` 是单个账号级对象，包含当前进度和 `models[]`，以及最近三个已完成窗口的 `history[]`；每个历史窗口也包含自己的 `models[]`，只提供汇总，不含逐请求清单。进程重启会保留已完成窗口；停止监控并开始新会话后，界面不显示旧会话历史。

手动采集会请求管理 API，不发送模型请求，也不重置采样会话。关闭再开启自动管理会开始新会话并清除本轮采样进度。

从旧15次质量窗口口径升级时，账号窗口及连续异常/健康计数重新累计，不沿用旧窗口或计数；已有冷却、恢复试运行、人工保护和调度所有权保留。

规则页的“恢复默认设置”只还原当前平台常开、优秀、良好、一般、备用五组的规则与优先级；操作后仍须点击“保存规则”才会生效。与出厂默认值不同的参数以绿色显示，保存后仍保留标记；改回出厂默认值后标记消失。

优秀组可另行启用倍率独占筛选：候选需达到独占缓存下限和首字时间上限，且可选满足低倍率条件；符合条件的账号中只保留倍率最低者。样本不足或独占条件不满足时，账号退出独占筛选但不会因此单独触发普通质量停用。

## 常开组临时状态

常开组忽略质量和倍率策略，并与优秀、良好、一般、备用组的故障切换独立。账号读取后，如果宿主报告 API Key 账号仍有效且未过期，并带有临时限流、过载或暂时不可调度字段，插件会在查询大量用量记录前调用一次无请求体的 `POST /admin/accounts/{id}/clear-error`。这需要管理 API 密钥具备 `accounts.recover` 权限。

清理只针对活跃、未过期账号的临时宿主状态，不会清理 `status=error`、凭证错误或其他需要人工处理的账号错误。此类账号保持人工处理状态；人工修复宿主状态后，自动观察会继续，插件仍保留并遵守调度设置的所有权记录。

普通组遇到临时限流、过载或暂时不可调度信号时，会立即关闭该账号并转入下一可用组。冷却到期后，账号按原分组和原优先级参与恢复候选；被选为候选时才尝试清理仍有效的临时宿主字段并开始试运行。清理、权限或宿主确认失败时账号保持关闭并等待退避重试。

## 故障恢复与人工修改

默认每个平台同时只试运行一个普通恢复候选。多个候选到期时按优秀、良好、一般、备用的固定顺序选择。候选使用原组优先级，不会移入较低组；稳定的低优先级后备组在试运行期间保持开放。候选通过恢复观察后，后备组账号才按其原有设置关闭。

恢复至少需要两个健康账号窗口和默认至少 300 秒的观察时间；每个窗口均按账号总指标判断，模型与请求类型的健康明细不分别要求恢复。若最长观察期限 `max(600 秒, 3 × recovery_seconds)` 内没有足够的完整流量，插件会延后下一次尝试，不增加故障次数。重试时间和观察进度保存在宿主插件 KV 中，进程重启后继续使用。

重复故障会按 300 秒基准逐次增加冷却，最长 24 小时。运行详情中的 `degradation_level` 是当前退避级别，不表示账号被改到其他组或优先级。

自动管理启用时插件记录原始值和目标值。若发现宿主调度开关或优先级已被人工修改，插件停止接管并保留当前设置。关闭自动管理、移除账号或修改配置时，只有仍等于插件目标值的设置才会恢复到记录的原始值。

宿主把账号标为 `error` 时会同时关闭调度。停止监控或移除账号时，插件保留宿主这次关闭，只恢复自身修改的优先级，避免再次开放异常账号。

进程重启保留健康、恢复、重试和人工保护状态。显式关闭后重新开启会创建新会话并重置健康及退避状态；人工操作账号当前的宿主调度开关和优先级成为新基线。尚未完成的非人工恢复所有权记录仍保留。卸载前先关闭自动管理并等待恢复完成。

## 运行详情与数据限制

运行状态包含实际二进制版本、执行主机、采样会话、最近与下次轮询以及账号状态。独立详情可显示账号质量窗口、坏/健康窗口、窗口内模型与请求类型诊断，以及故障和临时故障次数、恢复尝试与失败次数、最近故障、下次重试、退避级别、试运行开始时间和观察期限。没有发生的事件或尚不可用的指标显示为空或未知，不应解释为零。

当前宿主 `/admin/usage` 不提供 HTTP 失败状态字段或错误请求计数。502 等错误请求数量不受支持；界面应显示“宿主暂不提供”，不能将其报告为 `0` 或宣称支持统计。

操作记录显示最近 50 条，每页 10 条；运行详情从这些记录中筛选当前账号最近 5 条，按最新在前显示时间、操作与原因，并随轮询更新，没有记录时显示“暂无操作记录”。“清空”同时隐藏列表与运行详情中当前界面会话已加载的记录，不删除宿主 KV 中的历史记录，重新打开页面后记录可能再次出现。

## 安装与权限

日常安装使用已编译签名的 `.s2plugin`，无需自行构建。发行包、签名验证、发布公钥信任及卸载恢复步骤见[构建与安装指南](../PACKAGING.md)。宿主版本范围为 `>=0.2.23 <0.3.0`，推荐按 0.2.23 接口评估；真实部署兼容性尚未声明验证。

插件清单声明 `openai.oauth.outbound_transport.v1` 能力。这个出站传输能力与管理 API 的 API Key 调度是不同功能；若宿主的该能力槽已绑定其他插件，启用前应核对宿主如何处理传输绑定。

插件只使用管理 API 和宿主插件 KV，不直接读取宿主数据库。密钥通过 `x-api-key` 请求头访问管理 API。按实际部署密钥权限目录授予以下所需访问：

| 操作 | 权限或端点 |
| --- | --- |
| 读取账号 | `accounts.read` |
| 读取用量 | 用量记录读取权限；参考权限目录为全局 `usage.read` |
| 读取上游倍率快照 | `/admin/accounts/upstream-billing-rates` |
| 更新调度开关 | `accounts.status` |
| 更新优先级 | `accounts.schedule` |
| 清理符合条件的临时宿主状态 | `accounts.recover` |

受限密钥还需配置允许的账号、平台和分组。参考宿主的倍率快照端点可能不接受普通受限账号范围密钥；以实际部署版本权限配置为准。自动管理没有多执行节点间的分布式协调；部署时确保只有预期的一个实例负责管理。

### Docker 地址

- 插件和管理 API 在同一容器：使用该容器实际监听地址，例如 `http://127.0.0.1:8080`。
- 跨容器访问：使用同一 Docker 网络内的服务名和容器端口，例如 `http://sub2api:8080`。
- 容器内的 `localhost` 指向当前容器，不会自动指向物理宿主机。插件会补全 `/api/v1` 前缀。

## 本地开发

安装 Go 1.25.0 或更高版本后运行：

```sh
go test ./...
go vet ./...
node --check ui/assets/app.js
node --check tests/ui-browser.js
```

`tests/runtime_test.go` 使用本地 HTTP fixture 验证插件协议、管理 API 调度写入、采集和恢复，不访问真实账号。`tests/ui-harness.html` 与 `tests/ui-browser.js` 用于模拟宿主 Bridge 的浏览器回归测试。

```sh
python -m http.server 4183 --bind 127.0.0.1
```

通过支持 Playwright 的浏览器打开 `http://127.0.0.1:4183/tests/ui-harness.html` 执行 UI 测试。构建脚本、Ed25519 签名和跨平台产物说明见[构建与安装指南](../PACKAGING.md)。

## 暂不支持

- OAuth 账号自动调度。
- 账号余额和当天费用统计。
- 自动开启上游倍率探测。
- 自动清除账号状态错误、凭证错误或其他需要人工处理的宿主错误。
- 502 等错误请求统计；宿主 `/admin/usage` 当前不提供所需字段。
- 多执行节点之间的分布式协调。
