# 使用指南

本文介绍 0.1.0 的实际行为。截图和示例数据均为模拟内容。

## 账号与调用组

插件只对明确添加的 API Key 账号执行自动调度；不会自动管理 OAuth 账号。各平台独立管理账号分组和规则。

| 调用顺序 | 调用组 | 默认优先级 | 说明 |
| --- | --- | ---: | --- |
| 1 | 优秀 | 6 | 可选启用低倍率独占筛选 |
| 2 | 良好 | 7 | 前一组没有可调用账号时接续 |
| 3 | 一般 | 8 | 前两组没有可调用账号时接续 |
| 4 | 备用 | 9 | 前三组没有可调用账号时接续 |
| - | 临时 | 99 | 不参与自动调用；新账号默认进入此组 |

组顺序固定，组内优先级可按平台修改。拖动账号可以移组。自动管理开启后，连接、账号、规则及组内调用设置会锁定；修改前须关闭自动管理。

账号监控按调用组展示正常账号和不可调用账号；空的调用组会隐藏，临时组有账号时会显示。账号管理列出所有已纳管账号，包括异常账号。调度状态显示宿主是否开放该账号参与调度，不表示账号此刻正在处理请求。

## 倍率

新账号默认使用上游倍率方案。有效的上游快照显示为上游倍率；快照不支持、缺失、过期或读取失败时，采用默认 `1.0×`，显示“上游不支持 默认 1.0×”。不会自动切换到账号保存的固定倍率。明确选择固定方案后，才采用该账号的固定值。

插件不会自动开启宿主的上游倍率探测。需要上游倍率时，先在宿主启用探测，并确认管理 API 密钥有权读取倍率快照。`1.0×` 默认值照常参与分组规则；例如倍率上限为 `0.2×` 时会超过上限。

## 采样与规则

启用自动管理后才开始用量采样。默认采样间隔为 60 秒，允许设置 15 至 3600 秒。每次从关闭转为启用都会开启新的采样会话；关闭后监控界面不再使用旧会话数据。进程重启本身不会重置会话或人工操作状态。

| 规则 | 默认值 | 口径 |
| --- | ---: | --- |
| 缓存命中比例下限 | 80% | 最近最多 20 次调用按 Token 加权；默认至少需要 20 次有效调用，可设置为 1 至 20 次 |
| 平均首字时间上限 | 10,000 ms | 最近 20 个有效样本的平均值；有效样本不足时不触发此项 |
| 有效倍率上限 | 0.2× | 当前选择的上游倍率或固定倍率 |
| 连续异常评估次数 | 3 次 | 连续采样评估命中规则后暂停调用，不是模型请求失败次数 |
| 异常冷却时间 | 5 分钟 | 冷却结束后重新采样，再参与组内选择 |

缓存比例计算如下：

```text
cache_read_tokens / (input_tokens + cache_creation_tokens + cache_read_tokens)
```

首字时间独立采集，最多扫描 5000 条记录。数据不完整、分页失败或样本不足时，受影响指标显示未知，不会当作 0。手动请求触发一次管理 API 采集，不会发送模型请求，也不会重置采样会话。

优秀组的倍率独占筛选默认倍率阈值为 `0.05×`，并单独配置缓存下限（默认 80%）及平均首字时间上限（默认 10,000 ms）。满足倍率条件的候选中只保留倍率最低的账号。缓存或首字时间样本不足时暂不据此淘汰候选；独占条件不满足会退出独占筛选，但不会因此单独触发普通异常停用。

## 人工修改与恢复

启用时插件记录宿主原有优先级和调度状态，通过宿主管理 API 调整已纳管账号，并将恢复信息保存在宿主插件 KV 中。若检测到有人在宿主侧修改优先级或调度状态，插件保留当前设置并停止自动覆盖该账号。人工开启、仍可调用的账号也可能影响后续组的开放，以保持组间顺序。

关闭自动管理后，插件按所有权记录恢复其接管的值。若当前值与插件最后写入值不一致，会保留人工修改。有未完成的恢复动作时，不应更换管理连接或执行节点；卸载前先关闭自动管理并确认恢复完成。

“可自动恢复”表示异常冷却结束后重新采样并参与组选择；“用户手动操作”表示插件保留人工设置，不自动恢复或覆盖。点开账号状态可在独立详情窗口查看不可调用原因和恢复安排。“调度中”只表示宿主调度开关开启，不代表正在处理请求。

关闭并重新启用插件监控只会开启新监控会话，不会清除上游真实限流或宿主账号错误。当前版本没有插件内的宿主错误重置或限流清除功能。

操作记录显示最近 50 条，每页 10 条。当前清空操作仅隐藏插件界面会话中已加载的记录，不会删除宿主 KV 中保存的记录；重新打开页面后，历史记录可能再次出现。

## 安装与权限

日常安装使用已编译签名的 `.s2plugin`，无需自行构建。发行包、签名验证、发布公钥信任及卸载恢复步骤见[构建与安装指南](../PACKAGING.md)。宿主版本范围为 `>=0.2.23 <0.3.0`，推荐按 0.2.23 接口评估；真实部署兼容性尚未声明验证。

插件清单声明 `openai.oauth.outbound_transport.v1` 能力。这个出站传输能力与管理 API 的 API Key 调度是不同功能；若宿主的该能力槽已绑定其他插件，启用前应核对宿主如何处理传输绑定。

插件只使用管理 API 和宿主插件 KV，不直接读取宿主数据库。密钥通过 `x-api-key` 请求头访问管理 API。按实际部署密钥权限目录授予以下所需访问：

| 操作 | 权限或端点 |
| --- | --- |
| 读取账号 | `accounts.read` |
| 读取用量 | 用量记录读取权限；参考权限目录为全局 `usage.read` |
| 读取上游倍率快照 | `/admin/accounts/upstream-billing-rates` |
| 更新调度开关 | `accounts.status` |
| 更新优先级 | `accounts.schedule` |

受限密钥还需配置允许的账号、平台和分组。参考宿主的倍率快照端点可能不接受普通受限账号范围密钥；以实际部署版本权限配置为准。

### Docker 地址

- 插件和管理 API 在同一容器：使用该容器实际监听地址，例如 `http://127.0.0.1:8080`。
- 跨容器访问：使用同一 Docker 网络内的服务名和容器端口，例如 `http://sub2api:8080`。
- 容器内的 `localhost` 指向当前容器，不会自动指向物理宿主机。插件会补全 `/api/v1` 前缀。

## 本地开发

安装 Go 1.25.0 或更高版本后运行：

```sh
go test ./...
go vet ./...
node --check ui/assets/app.js
node --check tests/ui-browser.js
```

`tests/runtime_test.go` 使用本地 HTTP fixture 验证插件协议、管理 API 调度写入、采集和恢复，不访问真实账号。`tests/ui-harness.html` 与 `tests/ui-browser.js` 用于模拟宿主 Bridge 的浏览器回归测试。

```sh
python -m http.server 4183 --bind 127.0.0.1
```

通过支持 Playwright 的浏览器打开 `http://127.0.0.1:4183/tests/ui-harness.html` 执行 UI 测试。构建脚本、Ed25519 签名和跨平台产物说明见[构建与安装指南](../PACKAGING.md)。

## 暂不支持

- OAuth 账号自动调度。
- 账号余额和当天费用统计。
- 自动开启上游倍率探测。
- 插件内重置宿主错误、清除限流或清除临时不可调度状态。
- 多个执行节点之间的分布式协调。
